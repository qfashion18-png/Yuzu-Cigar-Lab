## Payment Issue Triage

Owner: commerce/support operator

1. Search by customer email, Stripe Checkout Session ID, Stripe Customer ID, PaymentIntent ID, or Yuzu order ID.
2. Check Stripe Dashboard for payment state, risk review, refunds, disputes, and receipt delivery.
3. Check the Yuzu backend order record for compliance status, fulfillment status, and webhook processing status.
4. If payment succeeded but no Yuzu order exists, replay or reprocess the Stripe webhook after confirming event signature and idempotency.
5. If payment failed, send the customer the Stripe-hosted retry or Customer Portal path where applicable.

## Refund Triage

Owner: commerce/support operator

1. Confirm requester identity and order ownership.
2. Check fulfillment status before refunding physical products.
3. Record refund reason, evidence, operator, Stripe refund ID, and customer message.
4. For subscriptions, confirm whether the action is refund only, cancellation only, or both.
5. Use Stripe as the payment action surface and Yuzu as the audit/order status surface.

## Failed Webhook Replay

Owner: backend operator

1. Identify failed Stripe event IDs from logs or the webhook event ledger.
2. Confirm the event is from the expected Stripe account and mode.
3. Reprocess idempotently; never create duplicate orders or duplicate subscription entitlements.
4. Mark the event as processed, failed, or held with a reason.
5. If replay fails because of missing catalog, age, shipping, or tax data, open a compliance hold.

## Compliance Hold Review

Owner: compliance/support operator

1. Review hold reason: age verification, restricted destination, shipping eligibility, tax/excise review, inventory mismatch, manual review, or payment mismatch.
2. Confirm the order has not been released for fulfillment.
3. Resolve only after the missing proof or corrected data is attached to the order record.
4. If the order cannot legally or operationally ship, cancel fulfillment and start refund triage.
5. Record the operator, decision, timestamp, and evidence reference.

## Age Verification Review

Owner: compliance/support operator

1. Confirm the vendor transaction ID and decision state.
2. Do not collect or store raw identity documents in the storefront.
3. Store only redacted vendor metadata and the decision needed for audit.
4. Reject checkout or hold fulfillment if verification is missing, failed, expired, or mismatched.
5. Re-run verification only through the approved vendor workflow.

## Incident Playbooks

Owner: incident commander

- Stripe outage: pause checkout by clearing `STRIPE_LAUNCH_CATALOG_READY`, post a checkout status banner, monitor webhooks, and reconcile delayed events when Stripe recovers.
- API outage: keep static catalog online, disable checkout CTA through environment/config, investigate Lambda/API Gateway/RDS health, then replay failed customer attempts from logs where possible.
- RDS outage: stop fulfillment release, keep Stripe webhook intake idempotent, queue events, restore from backups only through the approved database runbook.
- Webhook replay backlog: sort by event creation time, reprocess idempotently, and escalate events that would create duplicate orders or subscription entitlements.
- Age-verification vendor outage: block new tobacco checkout, keep paid orders on compliance hold, and notify support operators of the manual-review pause.
- Shipping provider outage: keep payment capture separate from fulfillment release, hold paid orders, and notify affected customers before label retry.

## Refund And Cancellation Workflow

Owner: commerce/support operator

- Verify requester identity, order ownership, fulfillment state, and subscription state.
- Confirm operator role allows refunds or cancellations.
- Use Stripe for money movement and Billing cancellation; use Yuzu for order/subscription status, evidence, and audit history.
- Record reason, amount, Stripe refund ID or subscription action ID, customer message, and operator.
- For fulfilled tobacco shipments, attach delivery/adult-signature evidence before deciding partial refund, replacement, or denial.

## Chargeback Response Workflow

Owner: commerce/support operator

- Gather Stripe dispute ID, Checkout Session, PaymentIntent, customer email, order ID, shipment tracking, adult-signature proof, age-verification decision, support history, and refund/cancellation history.
- Submit only accurate evidence through Stripe.
- Mark the Yuzu order with dispute status and the evidence deadline.
- Review recurring dispute patterns weekly for compliance, fulfillment, or product-page copy changes.

## Inventory Correction Workflow

Owner: fulfillment operator

- Correct source inventory first, then update Yuzu catalog/order records.
- Re-run Stripe product/price sync only after the Yuzu SKU, price, publish status, and stock policy are correct.
- If a paid order cannot be fulfilled, open a compliance/fulfillment hold and start support/refund triage.
- Never edit a Stripe Price amount in place for historical orders; create a new Price and update the active catalog mapping.
